# 爆文分析方法说明

本文档说明 ontentops-platform 项目里"爆文分析 → 规则生成"的完整方法。
用于回顾、面试讲解、二次开发参考。

---

## 一、数据源：红狐 API 给的字段

每条爆文入库后，`viral_articles` 表存了：

| 字段 | 含义 | 当前用途 |
|---|---|---|
| work_id | 笔记唯一 ID | 去重键 |
| title | 标题 | 自变量来源 |
| content | 正文 | 自变量来源 + 向量化 |
| author | 作者昵称 | 存着，未分析 |
| note_url | 笔记链接 | 存着，未分析 |
| likes | 点赞数 | 因变量来源 |
| collects | 收藏数 | 因变量来源 |
| comments | 评论数 | 因变量来源 |
| embedding | 1024 维向量 | 检索用 |
| platform | 平台 | 固定"小红书" |

**红狐不给的字段**（想拿但拿不到）：
- 作者粉丝数
- 曝光量
- 点击率
- 完读率
- 涨粉数

这是平台数据保护的结果。所有"过程指标"都锁在平台后台，外部爬虫拿不到。

---

## 二、变量定义

### 因变量（Y）：互动量

```python
score = likes + collects + comments
```

**统计量**：中位数，不是均值。

**为什么用中位数**：互动量是长尾分布。
- 76 条样本里，最高一条 346,975
- 中位数只有 4,744
- 均值 15,408 —— 被少数爆款完全拉偏

均值对极端值不稳健，中位数不受影响。

### 自变量（X）：当前已分析的

| 变量 | 类型 | 定义 |
|---|---|---|
| has_number | 二值 | 含表示"数量"的数字 |
| has_pain | 二值 | 点出具体困境 |
| has_trend | 二值 | 蹭近 3 个月热点 |
| emotion | 三分类 | 0 陈述 / 1 疑问 / 2 强情绪 |

**未来候选自变量**：关键词密度、长尾词命中、标题字数、疑问句式、第二人称、段落结构。

## 三、方法：六步流程

```
① 拉数据
   SELECT title, likes, collects, comments
   FROM viral_articles
   WHERE title 非空

② 编码（LLM 打标）
   按编码手册定义，把标题批量喂给千问
   每批 20 条，输出 JSON

③ 分组
   按特征分两组（true / false）
   情绪分三组（0 / 1 / 2）

④ 算指标
   每组取中位数
   lift = 有特征组中位数 / 无特征组中位数

⑤ 输出规则文件
   写入 content/viral_title_patterns.json
   包含特征名、中位数、lift、样本量

⑥ 注入生成 prompt
   generate_title / write_article 读 JSON
   把 lift > 1.2 的规则拼进 prompt
```

---

## 四、指标解释

| 指标 | 公式 | 含义 |
|---|---|---|
| median_with | 组内中位数 | 有该特征时典型互动量 |
| median_without | 组内中位数 | 无该特征时典型互动量 |
| lift | 前者 / 后者 | 相对倍数（率比） |
| count_with | 组内条数 | 样本量 |
| count_without | 组内条数 | 样本量 |

**样本门槛**：每组至少 10 条，低于此跳过。

**lift 判读**：
- 1.0 → 无差异
- 1.2 → 提升 20%，可关注
- 1.5 → 明显效应
- 2.0 → 强效应
- < 1.0 → 反向，警惕（可能打标错或共线）

## 五、当前结果（76 条样本）

| 特征 | lift | 判读 |
|---|---|---|
| has_number | 0.65 | 反常，暂不使用 |
| has_pain | 0.63 | 反常，暂不使用 |
| has_trend | — | 样本不足（6 条） |
| emotion_0 | 中位数 1892 | 基线 |
| emotion_1 | 中位数 3457 | 1.8 倍 |
| emotion_2 | 中位数 5650 | 3.0 倍 |

**结论**：情绪有明确单调趋势，已落地使用。数字和痛点待编码手册修正后重跑。

## 六、方法能回答什么、不能回答什么

### 能回答
- 在**已爆笔记**里，哪个特征和更高互动量相关
- 各特征的相对强度
- 趋势方向

### 不能回答
- **因果**："用情绪能提升互动" —— 只能说"相关"
- **"怎么爆"**：红狐全是已爆数据（≥1000 互动），没有"未爆"对照组
- **过程机制**：看不到曝光、点击、完读，无法解释"为什么这条更火"

## 七、方法论对应

这套代码本质是**内容分析法 + 准实验设计**，对应心理学的框架：

| 代码实现 | 心理学对应 |
|---|---|
| CODING_MANUAL | 编码手册 |
| LLM 打标 | 编码员 |
| 分组算中位数 | 组间对比 |
| lift | 率比 / 相对风险 |
| 样本量门槛 | 统计效力 |
| 打标准确性 | 编码信度（Kappa） |

---

## 八、已知局限与改进方向

### 局限一：打标效度未检验
LLM 按编码手册打标，但没做信度检验（Kappa）。
下一轮迭代：同一批标题两次打标，算一致率。

### 局限二：因变量过于粗糙
likes + collects + comments 合并成一个数。
三种互动行为的意义完全不同：
- 点赞 = 轻互动
- 收藏 = 高意图（我要留着用）
- 评论 = 高参与

样本量到 200+ 时，应拆分三个因变量分别分析。

### 局限三：只覆盖"已爆"样本
红狐只收录高互动笔记。这批数据没有"没爆"的对照。
只能回答"爆了的里面有什么共性"，不能回答"什么内容更容易爆"。

### 局限四：过程指标全缺失
没有曝光、点击率、完读率。
只能看结果，看不到过程。

### 改进路径
1. 样本量扩大到 200+，拆分因变量
2. 做 Kappa 信度检验，修正编码手册
3. 用自己的账号发内容，从后台获取过程指标
4. 长期目标：建立"自己的数据 + 过程指标"的双层分析体系

---

## 九、一句话总结

> 一套方法（编码 + 分组 + 算 lift），一个因变量（互动量中位数），四个自变量（数字 / 痛点 / 热点 / 情绪）。
> 红狐给的数据有限，只能在"已爆笔记"的范围内找规律。突破天花板的方法是用自己的账号发内容，拿过程数据。

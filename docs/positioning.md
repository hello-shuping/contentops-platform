# 项目定位

## 一句话

ContentOps Platform 不是"AI 写作工具"，是"内容运营决策系统"。

## 核心洞察

内容运营的完整闭环：

① 洞察（分析平台爆款）—— 找出什么是"好"
      ↓
② 决策（定选题、定策略）—— 决定"做什么、怎么写"
      ↓
③ 执行（撰写、排版、发布）—— 把内容做出来
      ↓
④ 复盘（分析自己账号数据）—— 评估"好不好"，调整下一轮

## 三个判断

**一、"写"是最不值钱的环节。**

多数人以为内容运营 = 写文章。但真正决定成败的，是前期的洞察和后期的复盘。AI 替代不了①和④，但能把③压缩到极致。

**二、要建的是"决策系统"，不是"写作系统"。**

- 创作者：今天灵感来了，写什么
- 操盘手：市场上什么火，我的账号在什么阶段，下一步该打哪张牌

**三、工具和闭环的对应关系。**

| 环节 | 工具 | 作用 |
|---|---|---|
| ① 洞察 | `analysis_viral_title.py` → `viral_title_patterns.json` | 从爆文里挖规律 |
| ② 决策 | `brainstorm_topics` | 定方向 |
| ③ 执行 | `generate_title` / `write_article` / `polish_content` / `check_originality` / `auto_revise` | 快速产出 |
| ④ 复盘 | `analyze_stats`（待补：周报/月报/归因） | 调策略 |

**最值钱的是①和④，最不值钱的是③——但③被 AI 解决了。**

## 对"该做什么"的约束

- 加新功能时，先问：它服务①/②/④，还是③？
- 服务③的，能省则省
- 服务①/②/④的，值得做深

## 对"该采多少数据"的约束

数据是①的原料，也是④的原料。数量不如颗粒度。一周精采 20-30 条，认真分析，持续迭代，比爬 1 万条垃圾数据更有效。
